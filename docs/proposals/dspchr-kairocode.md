# dspchr の ADR の案: プロセスの無いエージェントも、同じサイドバーに並ぶ

KairoCode の ADR 0004 の段階 2 を、dspchr の側の判断として書いた案です。dspchr のリポジトリで `scripts/new-adr` から起こし、dspchr の流儀で直してから使ってください。KairoCode の側からは dspchr を編集しません。

---

# ADR-NNN: プロセスの無いエージェントも、同じサイドバーに並ぶ

dspchr は「エージェントはプロセスのように感じられるべき」として作ってきた。並ぶのは PTY の中で走っているもので、状態はそのプロセスを見て決める（[ADR-005](0005-Agent-状態は-CPU-time-delta-と画面ハッシュで推定する.md)、[ADR-039](0039-Agent-が自分の状態を言えるようにする-ただし言わなくても動く.md)）。

KairoCode（`../kairocode`）は、この前提の外にいる。セッションを耐久のワークフロー（kairo）として動かすので、**承認を待つ間はプロセスが無い**。何時間後に、別の端末から承認しても続く。落ちても続きから進む。プロセスを見ている限り、待っている KairoCode は「無い」ことになる。

**並べる。** プロセスは無いが、何を待っているかは分かっている。見えないところで待っているもののほうが、見えていなければならない。

### デーモンが KairoCode のサーバーのクライアントになる

[ADR-042](0042-リモートのセッションは-同じサイドバーに並ぶ.md) で、デーモンが別のデーモンのクライアントになり、向こうのセッションを同じ一覧に並べた。同じ形をとる。

- 手元の KairoCode のサーバーは、`~/.local/share/kairocode/server.json`（0600）にアドレスとトークンを書く。デーモンはこれがあればつなぐ。無ければ何もしない。
- デーモンはセッションの一覧と出来事（SSE）を購読し、サイドバーの行（`ReadRows` / `RowList` の形）にする。
- 行の状態は KairoCode が言う。推測しない（[ADR-039](0039-Agent-が自分の状態を言えるようにする-ただし言わなくても動く.md) の「報告があれば推測しない」と同じ）。

### 待っているものに、ここで答える

承認待ちと要確認（落ちたときに走っていたコマンドが、実行されたか分からない）は、**中央のダイアログ**（[ADR-092](0092-yesno-は真ん中の箱で訊く-下のバーは-打っているものと知らせのため.md) の形）で訊く。答えは KairoCode の `POST /approvals/{key}`、`POST /reviews/{key}` に送る。既定は `no`。

### ペインを開くと、続きが始まる

プロセスの無い行を選んでペインを開くと、`kairocode --session <ID>` を起動する（[ADR-068](0068-opencode-は-id-ではなく-続き-で-resume-する.md) の resume の一種）。

### 木を見せる

KairoCode のサブエージェントとワークフローは、親の下に木として並べる。要件 §24 の「ユーザーが知らないところで Agent を spawn しない」は、KairoCode が spawn するものを**ユーザーが見られる**ことで満たす。dspchr が spawn するわけではない。

### 使用量

トークンは KairoCode が記録している。transcript を読まず、一覧の行に入っている値を出す（[ADR-066](0066-コストはトークンで数える-ドルでは数えない.md) の単位のまま）。

**未確認のこと（起票の前に確かめる）:**

- `ReadRows` / `RowList` が、プロセスの無い行（PTY の無い行）を表せるか。
- KairoCode のサーバーの API の欄。dspchr が話すのは KairoCode 自身の API（KairoCode の設計 8.1 節）で、opencode 互換の層（KairoCode の ADR 0002）ではない。一覧の欄（状態、使用量、承認と要確認のキー、子の木）は、KairoCode の M2 で決める。
