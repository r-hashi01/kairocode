# 0033 端末の画面の下の領域を、Codex と同じ仕組みで自前で描く

- 状態: 提案
- 日付: 2026-10-28
- 関連: ADR 0010（端末の画面、Bubble Tea v2）、0032（端末の通知）

## 背景

`kairo` の画面は、書き終えた会話を端末の履歴（スクロールバック）にそのまま書き、その下の領域（書きかけの返事、動いている呼び出し、`Working…`、入力欄、状態の行）だけを描き直す形です（インライン方式）。描き直しは Bubble Tea v2 の描画（`cursedRenderer`）に任せています。

この描画には、次の性質があります（`insertAbove` のソースで確かめた。2026-10-28）。

- 下の領域は、その上端から描き直す。上端は画面の上で固定。
- 会話の行を上に書くときは、画面全体を上にスクロールして差し込む。下の領域は押し下げられない。

そのため、下の領域が低くなると、その分だけ下の端（入力欄、状態の行）が上に浮きます。画面が下まで埋まっていても浮きます（利用者の指摘、2026-10-28）。`18ac90d` で、領域を縮めずに上を空行で埋める手当てをしましたが、空行が残ります。

Codex（`codex-rs/tui`）は、同じインライン方式で、この浮きが起きないように作っています。利用者の判断で、Codex と同じ仕組みにします（2026-10-28）。

Codex の仕組み（`insert_history.rs` の全体と、`tui.rs` の `draw` を読んだ）:

1. **下の領域（viewport）の位置を、自分で持つ。** 画面の何行目から何行かを、自前の端末層（`custom_terminal`）が覚えている。
2. **会話の行は、スクロール範囲を使って、下の領域より上だけに書く。** `DECSTBM`（スクロール範囲）を「画面の一番上から下の領域の直前まで」にして、その中で改行しながら書く。動くのはその範囲だけで、下の領域は動かない。
3. **下の領域が画面の一番下に無いとき（始めたばかりの画面、領域が低くなった後）は、会話の行を書く前に、領域を下に押し下げる。** 領域の上端から画面の下までをスクロール範囲にし、逆スクロール（`ESC M`）で、書く行の数だけ（画面の下までの空きを上限に）押し下げる。
4. **下の領域が高くなって画面の下を越えるときは、画面全体を上にスクロールして、領域の下を画面の下に合わせる。** 低くなるときは上端を変えず、次に会話の行を書くとき 3 で戻る。
5. **書きかけの返事は、下の領域に描かない。** 行が書き終わるたびに会話の側へ移す。下の領域の高さは、ほぼ一定（作業中の状態の行、入力欄、案内の行）。
6. **同期描画**（`DEC 2026`、synchronized output）で、1 回の描き直しを 1 つにまとめて送る。
7. スクロール範囲がうまく働かない端末（Zellij）では、別の書き方（全画面で書き直す）に切り替える。

## 決定（案）

1. **描画を Bubble Tea から外す。** `tea.WithoutRenderer()` で起動し、Bubble Tea にはキー入力、貼り付け、焦点、背景色の問い合わせなどの受け取りと、画面の状態（`model`）の更新だけを任せる。描くのは KairoCode の新しい層（`internal/tui/screen`）。
   - Bubble Tea が描画を外したときに、生モード、ブラケット貼り付け、焦点の知らせなどの端末の設定を自分でするかは、作るときに確かめる。しないものは、新しい層が設定し、終わるときに戻す。
2. **新しい層は、Codex の 1〜4 と 6 をそのまま行う。**
   - 下の領域の位置（上端の行と高さ）を持つ。起動時に、カーソルの位置を端末に問い合わせて（`DSR`）、上端を決める。
   - `model` の `View` の文字列を行に分け、前の描画と違う行だけを、その行の位置に直接書く（行ごとの差分）。カーソルの位置と形も新しい層が置く。
   - 会話の行（今の `Println` の代わり）は、2・3 の書き方で、下の領域の上に書く。
   - 下の領域の高さが変わったときは、4 の扱いにする。`18ac90d` の「縮めない」手当ては外す。
   - 画面の大きさが変わったら、下の領域を描き直す。
3. **書きかけの返事は、下の領域に描かない（Codex の 5）。** 書き終わった行だけを会話の側に出す。動いている呼び出し、`Working…`、承認の画面は、これまでどおり下の領域に描く。
4. **Zellij では、Codex と同じく、スクロール範囲を使わない書き方にする**（環境変数 `ZELLIJ` で見分ける）。tmux はスクロール範囲を扱えるので、そのままにする。
5. 全画面の画面（フローのレビュー、`/plugin`、ADR 0010 の代替画面）は、今までどおり代替画面に描く。新しい層が、代替画面への出入りも行う。

実装に現れるところ: `internal/tui/screen`（新しい描画の層: 位置、差分、会話の行の書き込み、端末の設定）、`internal/tui/tui.go`（`View` の使い方、`print` の行き先、書きかけの行）、`internal/cli/chat.go`（起動の仕方）。

## 結果

- 画面が下まで埋まっていれば、入力欄と状態の行は、どの場面でも画面の一番下から動かない。始めたばかりの画面では、Codex と同じく上から伸びる。
- 空行の手当て（`18ac90d`）は要らなくなる。
- 描画を自前で持つので、Bubble Tea の版が上がっても描き方は変わらない。代わりに、端末ごとの違い（スクロール範囲、同期描画、全角の幅）を自分で扱う。
- テスト: 端末の動きを真似る小さな模擬の端末（カーソルの移動、行の消去、スクロール範囲、逆スクロール、行の挿入。テストのコードの中に書き、依存は足さない）を作り、Codex のテスト（`vt100` で画面の行を確かめる）と同じ形で確かめる。
  - 画面が埋まった後、下の領域が高くなる・低くなる・会話の行が書かれる、のどの順でも、入力欄の行が画面の一番下にある。
  - 始めたばかりの画面では、領域が上から下へ伸び、会話の行で押し下げられる。
  - 会話の行は、下の領域の内容を壊さず、その上に順に並ぶ。長い行の折り返し、全角の文字。
  - Zellij の書き方。
  - 本物の端末（iTerm2、Terminal.app、Ghostty、tmux の中）では手で確かめる。

## 検討した代替案

- **Bubble Tea の描画のまま、`18ac90d` の「縮めない」手当てを続ける:** 下は浮かないが、上に空行が残る。利用者の判断で、Codex と同じにする。
- **Bubble Tea の描画の外から、スクロール範囲の制御を直接送る（`tea.Raw`）:** Bubble Tea の描画は、カーソルの位置を自分の覚えている値からの相対で動かすので、外から動かすとずれて壊れる。
- **全画面方式（代替画面）にする:** 入力欄は固定できるが、会話を端末の履歴に残せず、スクロールや検索を自前で作ることになる。
- **端末の模擬にライブラリ（`charmbracelet/x/vt` など）を使う:** 依存が増える。テストに要る動きは限られるので、テストのコードの中に書く。
