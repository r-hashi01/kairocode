# 0025 プラグイン: 外のサービスへの接続とスキルの束、`/plugin` と `/plugin connect`

- 状態: 承認（2026-10-26）
- 日付: 2026-10-26
- 関連: ADR 0002・0018（プラグインは保留していた）、0003（フロー）、0022（MCP サーバー、カスタムツール、作用の型の宣言）、不変条件 3・4・6

## 背景

利用者が想像しているプラグインは、Dify、n8n、Zapier にあるような「外のサービスへの接続の部品」です。外への接続（MCP のようなもの）か、能力（スキルのようなもの）、またはその両方を足します（2026-10-26）。

3 つの製品の部品は、どれも次の 4 つでできています。
- 認証: 資格情報を部品と別に預かり、使い回す。
- 操作: アクション、サーチ。
- 起点: トリガー。
- 配り方: マーケットプレイス。

また、MCP が共通の口になりつつあります。Zapier は、つないだアプリの操作を MCP のサーバーとして出しています。

KairoCode には、ADR 0022 で MCP サーバーとカスタムツールを足しました。ただし、利用者が `kairocode.json` に生の設定（コマンド、URL、環境変数）を書く形で、次のものがありません。
- 認証（OAuth、キー）を預かる場所と、その状態（つながっているか、切れたか）を見る手段。
- まとめて入れる・外す手段。
- 説明（スキル）と一緒に配る手段。

## 決定

1. **プラグインは「MCP サーバー＋ KairoCode のマニフェスト」の束とする。** 中身の動きは MCP サーバーに任せ、MCP にないものをマニフェスト（`kairocode-plugin.json`）で補います。
   - **接続:** MCP サーバーの起動の仕方（`command`）か、リモートの URL（`url`）です。
   - **操作の作用の型:** ツールごとに `read`・`idempotent`・`real` を書きます（`*` の前方一致も書ける）。宣言のないものは実です（不変条件 3）。ADR 0022 の `tools` の宣言と同じ扱いです。
   - **資格情報:** 何が要るかを書きます。
     - `none`。
     - `key`: 名前の付いた値。環境変数かヘッダーで MCP サーバーに渡す。
     - `oauth`: リモートの MCP サーバーの OAuth（MCP の認可の仕様）。MCP の Go の SDK（`auth`）の認可コードの流れと、動的なクライアントの登録を使う。
   - **スキル:** `skills/` に置いたスキルを、エージェントが読めるようにします（ADR 0002 のスキルと同じ規則）。
   - プラグインは、接続だけ、スキルだけ、両方のどれでもよいとします。
   - Claude Code のプラグインの形（`.claude-plugin/plugin.json`、`skills/`、`.mcp.json`）も読みます。作用の型の宣言がないので、そのツールは実として扱います。
2. **置き場所と入れ方**
   - 利用者のプラグインは、データの置き場の `plugins/<名前>/` です。
     - `/plugin install <git の URL か手元のパス>` で入れ、`/plugin remove <名前>` で外します。
     - 入れたものは、git のコミットで固定します。更新は `/plugin update <名前>` で明示したときだけです。
   - プロジェクトのプラグインは `.kairocode/plugins/<名前>/` です。ADR 0022 のプロジェクトの MCP サーバーと同じく、最初に使うときに動かし方を聞きます。
3. **`/plugin connect <名前>`（資格情報）**
   - `key` のものは、TUI で値を聞きます（入力は伏せる）。
   - `oauth` のものは、ブラウザーを開き、手元の `127.0.0.1` のポートで戻りを受けます。リフレッシュトークンを預かり、切れる前に自動で更新します。
   - 値は OS の鍵の保管庫に置きます（macOS のキーチェーンは `security`、Linux の Secret Service は `secret-tool`。どちらもコマンドで呼び、依存を足さない）。保管庫がない環境では、データの置き場に権限 0600 のファイルで置き、そのことを知らせます。
   - 値は、MCP サーバーを起動するとき（環境変数）か、つなぐとき（ヘッダー）に読み、記録・ログ・エラーの文面には残しません（不変条件 6、ADR 0022 と同じ）。
   - `/plugin disconnect <名前>` で消します。
4. **`/plugin`（一覧と状態）:** 入っているプラグインごとに、次を見せます。
   - 名前、版（コミット）、利用者のものかプロジェクトのものか。
   - **接続の状態:** つながっている／未接続（`/plugin connect` が要る）／認証が切れた（更新に失敗した、サーバーが 401・403 を返した）／起動しない（エラー）／動かし方をまだ聞いていない（プロジェクトのもの）。
   - ツールの数と、それぞれの作用の型。スキルの名前。
   - 状態は、デーモンが持つ最新の結果（最後に起動・接続・更新したときの結果、最後の呼び出しの認証の失敗）から出します。kairo の記録には入れません（ワークフローの分岐に使わないため）。
   - 認証が切れたプラグインのツールを呼んだときは、モデルに「`/plugin connect <名前>` が要る」と返します。
5. **使い方:** ツールは `<プラグイン>_<ツール>` の名前で、ADR 0022 の外のツールと同じ仕組み（ターンの始めに定義を記録、作用の型で動かす、要確認）で、どのエンジンでも使えます。フローの `tool(...)` と `agent(...)` からも使えるようにします。今は、フローのこの 2 つが ADR 0022 の外のツールにつながっていないので、それを先に直します（ADR は要らない、穴の修正）。
6. **トリガーは、この ADR では決めない。** 手元のデーモンには外から呼べる URL がないので、ウェブフックを受けるには中継が要ります（M4 と重なる）。必要になったら別の ADR にします。

実装に現れるところ: `internal/runtime`（プラグインの読み込みと、ADR 0022 の外のツールへのつなぎ込み、資格情報の保管、OAuth、状態）、`internal/acp` と `internal/tui`（`/plugin`、`/plugin connect` の入力と、ブラウザーを開くこと）、`internal/cli`（`kairocode plugin ...`）、`internal/invariants`（`security`・`secret-tool` を起動してよいファイル）。

## 結果

- 利用者は、外のサービスへの接続を、生の設定を書かずに入れ、つなぎ、状態を確かめられます。認証が切れたことに、一覧と呼び出しの両方で気づけます。
- 接続の中身は MCP なので、既存の MCP サーバー（Zapier の MCP なども）をそのままプラグインにできます。
- 作用の型と資格情報の扱いは、KairoCode の約束（二重に動かない、秘密を残さない）のままです。
- テスト（実装のとき足す）
  - 偽の MCP サーバーのプラグインを入れて、ツールが宣言の作用の型で使える。
  - `key` の資格情報が、サーバーに渡り、記録（DB）に残らない。
  - 偽の OAuth のサーバーで、`/plugin connect` が認可コードの流れでトークンを得て、切れたら更新する。更新に失敗すると、一覧が「認証が切れた」になる。
  - サーバーが 401 を返すと、一覧が「認証が切れた」になり、モデルに `/plugin connect` が要ると返る。
  - プロジェクトのプラグインは、聞く前に起動しない。

## 検討した代替案

- **`kairocode.json` の `mcp` のままにする（ADR 0022）:** 生の設定を書く手間と、認証の状態が見えないことが残ります。プラグインの下の層として、`mcp` は残します。
- **Dify や n8n のように、プラグインのコードを KairoCode の中で動かす:** KairoCode は Go の単一のバイナリなので、別の言語の実行環境が要ります。また、ワークフローの中で動けば決定性が崩れます。MCP サーバーとして外で動かせば、どの言語でも書け、記録と再開の仕組みにも乗ります。
- **資格情報を `kairocode.json` に書く:** 平文で残り、プロジェクトの設定に紛れ込むおそれがあります。
