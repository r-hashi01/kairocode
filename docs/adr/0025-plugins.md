# 0025 プラグイン: 外のサービスへの接続とスキルの束、`/plugin` と `/plugin connect`

- 状態: 承認（2026-10-26）
- 日付: 2026-10-26
- 関連: ADR 0002・0018（プラグインは保留していた）、0003（フロー）、0022（MCP サーバー、カスタムツール、作用の型の宣言）、不変条件 3・4・6

## 背景

利用者が想像しているプラグインは、Dify、n8n、Zapier にあるような「外のサービスへの接続の部品」です。外への接続（MCP のようなもの）か、能力（スキルのようなもの）、またはその両方を足します（2026-10-26）。

3 つの製品の部品は、どれも次の 4 つでできています。
- 認証: 資格情報を部品と別に預かり、使い回す。
- 操作: アクション、サーチ。
- 起点: トリガー。
- 配り方: マーケットプレイス。

また、MCP が共通の口になりつつあります。Zapier は、つないだアプリの操作を MCP のサーバーとして出しています。

KairoCode には、ADR 0022 で MCP サーバーとカスタムツールを足しました。ただし、利用者が `kairocode.json` に生の設定（コマンド、URL、環境変数）を書く形で、次のものがありません。
- 認証（OAuth、キー）を預かる場所と、その状態（つながっているか、切れたか）を見る手段。
- まとめて入れる・外す手段。
- 説明（スキル）と一緒に配る手段。

## 決定

1. **プラグインは「MCP サーバー＋ KairoCode のマニフェスト」の束とする。** 中身の動きは MCP サーバーに任せ、MCP にないものをマニフェスト（`kairocode-plugin.json`）で補います。
   - **接続:** MCP サーバーの起動の仕方（`command`）か、リモートの URL（`url`）です。
   - **操作の作用の型:** ツールごとに `read`・`idempotent`・`real` を書きます（`*` の前方一致も書ける）。宣言のないものは実です（不変条件 3）。ADR 0022 の `tools` の宣言と同じ扱いです。
   - **資格情報:** 何が要るかを書きます。
     - `none`。
     - `key`: 名前の付いた値。環境変数かヘッダーで MCP サーバーに渡す。
     - `oauth`: リモートの MCP サーバーの OAuth（MCP の認可の仕様）。MCP の Go の SDK（`auth`）の認可コードの流れと、動的なクライアントの登録を使う。
   - **スキル:** `skills/` に置いたスキルを、エージェントが読めるようにします（ADR 0002 のスキルと同じ規則）。
   - プラグインは、接続だけ、スキルだけ、両方のどれでもよいとします。
   - Claude Code のプラグインの形（`.claude-plugin/plugin.json`、`skills/`、`.mcp.json`）も読みます。作用の型の宣言がないので、そのツールは実として扱います。
2. **置き場所と入れ方**
   - 利用者のプラグインは、データの置き場の `plugins/<名前>/` です。
     - `/plugin install <git の URL か手元のパス>` で入れ、`/plugin remove <名前>` で外します。
     - 入れたものは、git のコミットで固定します。更新は `/plugin update <名前>` で明示したときだけです。
   - プロジェクトのプラグインは `.kairocode/plugins/<名前>/` です。ADR 0022 のプロジェクトの MCP サーバーと同じく、最初に使うときに動かし方を聞きます。
3. **`/plugin connect <名前>`（資格情報）**
   - `key` のものは、TUI で値を聞きます（入力は伏せる）。
   - `oauth` のものは、ブラウザーを開き、手元の `127.0.0.1` のポートで戻りを受けます。リフレッシュトークンを預かり、切れる前に自動で更新します。
   - 値は OS の鍵の保管庫に置きます（macOS のキーチェーンは `security`、Linux の Secret Service は `secret-tool`。どちらもコマンドで呼び、依存を足さない）。保管庫がない環境では、データの置き場に権限 0600 のファイルで置き、そのことを知らせます。
   - 値は、MCP サーバーを起動するとき（環境変数）か、つなぐとき（ヘッダー）に読み、記録・ログ・エラーの文面には残しません（不変条件 6、ADR 0022 と同じ）。
   - `/plugin disconnect <名前>` で消します。
4. **`/plugin`（一覧と状態）:** 入っているプラグインごとに、次を見せます。
   - 名前、版（コミット）、利用者のものかプロジェクトのものか。
   - **接続の状態:** つながっている／未接続（`/plugin connect` が要る）／認証が切れた（更新に失敗した、サーバーが 401・403 を返した）／起動しない（エラー）／動かし方をまだ聞いていない（プロジェクトのもの）。
   - ツールの数と、それぞれの作用の型。スキルの名前。
   - 状態は、デーモンが持つ最新の結果（最後に起動・接続・更新したときの結果、最後の呼び出しの認証の失敗）から出します。kairo の記録には入れません（ワークフローの分岐に使わないため）。
   - 認証が切れたプラグインのツールを呼んだときは、モデルに「`/plugin connect <名前>` が要る」と返します。
5. **使い方:** ツールは `<プラグイン>_<ツール>` の名前で、ADR 0022 の外のツールと同じ仕組み（ターンの始めに定義を記録、作用の型で動かす、要確認）で、どのエンジンでも使えます。フローの `tool(...)` と `agent(...)` からも使えるようにします。今は、フローのこの 2 つが ADR 0022 の外のツールにつながっていないので、それを先に直します（ADR は要らない、穴の修正）。
6. **トリガーは、この ADR では決めない。** 手元のデーモンには外から呼べる URL がないので、ウェブフックを受けるには中継が要ります（M4 と重なる）。必要になったら別の ADR にします。

実装に現れるところ: `internal/runtime`（プラグインの読み込みと、ADR 0022 の外のツールへのつなぎ込み、資格情報の保管、OAuth、状態）、`internal/acp` と `internal/tui`（`/plugin`、`/plugin connect` の入力と、ブラウザーを開くこと）、`internal/cli`（`kairocode plugin ...`）、`internal/invariants`（`security`・`secret-tool` を起動してよいファイル）。

## 結果

- 利用者は、外のサービスへの接続を、生の設定を書かずに入れ、つなぎ、状態を確かめられます。認証が切れたことに、一覧と呼び出しの両方で気づけます。
- 接続の中身は MCP なので、既存の MCP サーバー（Zapier の MCP なども）をそのままプラグインにできます。
- 作用の型と資格情報の扱いは、KairoCode の約束（二重に動かない、秘密を残さない）のままです。
- テスト（実装のとき足す）
  - 偽の MCP サーバーのプラグインを入れて、ツールが宣言の作用の型で使える。
  - `key` の資格情報が、サーバーに渡り、記録（DB）に残らない。
  - 偽の OAuth のサーバーで、`/plugin connect` が認可コードの流れでトークンを得て、切れたら更新する。更新に失敗すると、一覧が「認証が切れた」になる。
  - サーバーが 401 を返すと、一覧が「認証が切れた」になり、モデルに `/plugin connect` が要ると返る。
  - プロジェクトのプラグインは、聞く前に起動しない。

## 検討した代替案

- **`kairocode.json` の `mcp` のままにする（ADR 0022）:** 生の設定を書く手間と、認証の状態が見えないことが残ります。プラグインの下の層として、`mcp` は残します。
- **Dify や n8n のように、プラグインのコードを KairoCode の中で動かす:** KairoCode は Go の単一のバイナリなので、別の言語の実行環境が要ります。また、ワークフローの中で動けば決定性が崩れます。MCP サーバーとして外で動かせば、どの言語でも書け、記録と再開の仕組みにも乗ります。
- **資格情報を `kairocode.json` に書く:** 平文で残り、プロジェクトの設定に紛れ込むおそれがあります。

## 実装（2026-10-26）

- 読み込み: `opencode.PluginDirs`（利用者のもの、次にプロジェクトのもの）、`internal/runtime/plugins.go`。プラグインのサーバーは ADR 0022 の `extServer` として `externals()` に加わり（`Plugin` にプラグインの名前）、ツールの名前、記録、作用の型、プロジェクトのものへの問いは ADR 0022 と同じ道を通ります。マニフェストの `tools` の宣言は、そのプラグインのツールにだけ効きます（`<プラグイン>_` を前に付ける）。スキルは `SkillDirs` が `<プラグイン>/skills` を足します。
- 資格情報: `internal/runtime/secrets.go`（`SecretStore`）。鍵は、利用者のプラグインが `<プラグイン>/<名前>`、プロジェクトのプラグインが `project/<フォルダーのハッシュ>/<プラグイン>/<名前>`（`PluginSecretKey`）です。利用者のプラグインと同じ名前のプロジェクトのプラグインでも、利用者の値は読めません。エラーの文面とログからは、そのプラグインの値を伏せます（`serverErr`）。値は、サーバーを起動するとき・つなぐときに `{secret:NAME}` へ入れ（`value`）、ないときは起動せず「未接続」とします。`{env:}` は、ADR 0022 と同じく利用者のものだけで広げます。
- CLI: `kairocode plugin [list|install|update|remove|connect|disconnect]`（`internal/cli/plugin.go`）。`connect` は端末のエコーを止めて値を読み、保管庫に置いてから、デーモンが動いていれば `POST /plugins/{name}/connected` で知らせます。デーモンは、そのプラグインのサーバーを止め（次の呼び出しで、新しい値で起動し直す）、「認証が切れた」を消します。
- API: `GET /sessions/{id}/plugins`、`GET /plugins?dir=`、`POST /plugins/{name}/connected`。ACP の `/plugin`（一覧）。
- TUI: `/plugin connect <名前>`・`/plugin disconnect <名前>` は、`tea.ExecProcess` で端末を `kairocode plugin connect` に渡します（`/login` のコマンドと同じ）。
- OAuth（3、2026-10-26）: `internal/runtime/oauth.go`。
  - **接続:** `kairocode plugin connect` が、MCP の Go の SDK の `auth.AuthorizationCodeHandler` で認可コードの流れ（PKCE）を進めます。クライアントは動的に登録します。マニフェストの `auth.client_id` があれば、事前に登録したものを使います。
    - ブラウザーは `open`・`xdg-open` で開き、URL も表示します。戻りは `127.0.0.1` の空いたポートで受けます。
    - 得たもの（クライアントの ID、トークンの端点、スコープ、アクセストークンとリフレッシュトークン）を、1 つの値として保管庫の `<プラグイン>/oauth` に置きます。
  - **デーモン:** 要求ごとにアクセストークンを `Authorization` に入れます。切れる前（`oauth2` の既定で 10 秒前）に更新し、新しいトークンを保管庫に書き戻します。
    - 更新を拒まれたとき（`invalid_grant` など）や、リフレッシュトークンがないときは、要求を送らずに `errRefused` を返し、一覧は「認証が切れた」になります。
    - トークンの端点に届かなかったとき、`invalid_grant` 以外のエラー（503 など）のときは、送っていないことは同じですが、「認証が切れた」にはしません（モデルには「送っていない」と返す）。
    - 同じ資格情報のトークンは、デーモンの中で 1 つが持ちます。更新の前に保管庫を読み直し、ほかの持ち手（別のデーモン）が更新していれば、それを使います（リフレッシュトークンは 1 度しか使えないことがあるため）。書き戻すのは、保管庫の値が更新の元にしたものと同じときだけです（その間に接続し直したり、切ったりしていれば書かない）。更新には 30 秒の期限があります。
    - 資格情報を付けた要求は、ほかのホストへのリダイレクトに従いません。
  - **戻りの受け口:** 聞いたときの `state` と一致する戻りだけを受けます（ほかのプロセスの呼び出しで、サインインを止められない）。認可のページは `https`（手元のアドレスなら `http`）だけを開きます。プロジェクトのプラグインのサーバーが、ほかの種類の URL を開かせることはできません。
  - **依存:** SDK の `auth` の API は `golang.org/x/oauth2` の型（`oauth2.Config`、`oauth2.Token`）で書かれているので、それを直接 import します。もとから SDK の依存として入っていたものです（`go.mod` の indirect から direct に変わるだけ）。利用者の了承を得て（2026-10-26）、AGENTS.md の許可済みの依存と、hook の一覧に足しました。
  - テスト: `TestPluginOAuth`（偽の認可サーバーと MCP サーバー。動的な登録、PKCE、コードの交換、更新と書き戻し、更新の拒否で「認証が切れた」、DB にトークンが残らない）。

決定からのずれ（実装で決めたこと。決定の趣旨は変えない）:
- **置き場所:** 利用者のプラグインは、データの置き場ではなく、利用者の設定の置き場（`$XDG_CONFIG_HOME/kairocode/plugins/<名前>`、なければ `~/.config/kairocode/plugins/<名前>`）です。`kairocode.json` やスキルと同じ置き場で、データの置き場（DB）を消しても残ります。資格情報のファイル（保管庫がないとき）も同じ置き場の `credentials.json`（0600）です。
- **値を聞く場所:** 値は ACP を通しません（記録とクライアントの間を通さないため）。端末の対話（`kairo`）は、上のとおり CLI に端末を渡します。ほかの ACP のクライアント（Zed など）の `/plugin connect` は、端末で `kairocode plugin connect <名前>` を実行するよう案内します。
- **macOS のキーチェーン:** `security add-generic-password` は値を標準入力から読めないので、値はコマンドの引数で渡します。その短い間、同じ利用者のプロセスの一覧から見え得ます。OAuth のトークンを更新して書き戻すときも同じです。Linux の `secret-tool` は標準入力で渡します。
- **認証の失敗の判定:** 「認証が切れた」とするのは、リモート（URL だけ）のプラグインのサーバーが、メッセージを運ぶ POST に HTTP の 401・403 を返したときだけです。これは `headers.RoundTrip` が型付きのエラー（`errRefused`）で返し、文面では判定しません。断られた POST は、サーバーが受け取っていないので、動いていないと言えます。
  - イベントの流れ（GET）の 401 や、JSON-RPC のエラーの文面（動いたツールが返した「403 Forbidden」など）、手元で起動するサーバーのエラーは、これに当たりません。結果が不明なら、これまでどおり不明として扱います（不変条件 4）。
- **作用の型の宣言:** マニフェストの `tools` は、そのプラグインのサーバー（マニフェストのパス）のツールにだけ効きます。同じ名前のほかのサーバーには効きません。
- **更新:** プラグインの版とコミットを、サーバーの指紋（`Spec`）に入れます。`update` の後、進行中のターンは、始めに一覧したサーバーとは違うものとして、そのツールを呼びません。
- テスト: `TestPluginTool`（未接続→接続、キーがサーバーに渡り DB に残らない、作用の型、スキル）、`TestPluginRefused`（呼び出しの 401 でモデルに `kairocode plugin connect` を返し、一覧が「認証が切れた」。接続し直すと戻る。起動時の 401 も同じ）、`TestProjectPluginAsks`（プロジェクトのものは聞く前に起動しない。スキルだけのもの）、`TestProjectPluginGetsNoUsersKey`、`TestPluginRefusedOnlyWhenTurnedAway`、`TestPluginDeclsAndErrors`、`TestPluginInstallConnectRemove`（git のコミットで固定、標準入力からの値、取り消し、外への削除の拒否）。
